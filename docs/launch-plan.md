# План запуска mos-dizel.ru — волны Л1–Л6

Дата: 2026-09-05 · Проект: ООО «ДТСНАБ» / МОС-ДИЗЕЛЬ · Студия ReBit.
Основа: порядок запуска, заданный владельцем 05.09.2026 (6 пунктов), + `docs/seo-plan-v3.md` (состав страниц, мета, DoD), `docs/marketing/direct-plan-v2.md` (кампании), `docs/discovery/client-answers-2026-09-04.md` (решения и вопросы клиенту).

**Чем этот план отличается от роадмапа seo-plan v3 §9.** Порядок изменён: (1) все страницы первой очереди верстаются ДО открытия сайта, а не после релиза лендинга; (2) хостинг — сервер студии вместо GitHub Pages, staging на поддомене `mos-dizel.rebit-pro.ru`, закрытом от роботов и без счётчиков; (3) Директ включается только после проверенных целей и почты. В части порядка и дат главный — этот план; содержимое страниц, мета и критерии приёмки — по seo-plan v3 и design-concept v3 без изменений.

## Решения по умолчанию (действуют, пока не поправите)

1. **«Все страницы SEO-плана» = главная + 13 страниц первой очереди (W1a + W1b) + политика ПДн + 404.** Страницы W2 (опт, гео МО и регионы, керосин ТС-1, оборудование, отзывы, о компании, блог) верстаются после запуска по графику seo-plan — иначе запуск уедет за пределы зимнего сезона.
2. **Продакшен-хостинг — тот же сервер студии** (второй vhost, тот же Docker-образ). GitHub Pages остаётся запасным вариантом; workflow не удаляем. 301 со старых доменов делаем на этом же nginx, когда клиент даст DNS.
3. Ящик отправителя пишем **zayavka@mos-dizel.ru** (в сообщении было «zayvka» — считаю опечаткой; если нужно именно так, скажите).
4. Даты — от 08.09.2026 (пн). Волны Л2 и Л3 идут параллельно Л1.

### Л2. Staging на mos-dizel.rebit-pro.ru — 09.09 → 10.09, дальше обновляется по мере Л1

| Задача | Детали |
|---|---|
| DNS + TLS | A-запись поддомена → сервер студии; сертификат Let’s Encrypt |
| Сборка staging | тот же Dockerfile; `VITE_METRIKA_ID` пуст (счётчиков в коде нет), `VITE_FORM_ENDPOINT` → шлюз Л3 |
| Закрытие от роботов | staging-vhost: `robots.txt` → `User-agent: * / Disallow: /`; заголовок `X-Robots-Tag: noindex, nofollow` на все ответы; по желанию — basic auth. Canonical в коде указывает на mos-dizel.ru — не мешает, noindex главнее |
| Деплой | `deploy.sh` на сервере: `git pull && docker compose up --build -d`; выкладываем сразу с готовым лендингом, страницы Л1 доезжают коммитами |

Готово, когда: staging открывается по HTTPS, в заголовках ответа есть X-Robots-Tag: noindex, в коде нет счётчиков.

### Л3. Универсальный шлюз форм rebit-forms — 10.09 → 12.09

| Задача | Детали |
|---|---|
| Каркас | отдельный репозиторий `rebit-forms`: PHP 8.3 + Slim 4, без БД; `POST /v1/{site}/lead` |
| Тенанты | `tenants/mos-dizel.yaml`: ключ сайта, allowlist origin (staging + прод), получатель, отправитель, тема письма, лимиты |
| Защита | honeypot, rate limit по IP и по сайту, ограничение длины полей, CORS строго по allowlist |
| Надёжность | при недоступном SMTP письмо в файловый спул, досылка кроном; алерт владельцу «в очереди N заявок» без содержимого |
| Каналы | email — основной; telegram — опциональный канал per-tenant для будущих клиентов (для mos-dizel выключен) |
| Docker | compose на сервере: gateway + Mailpit в dev-профиле; локально то же самое |
| Подключение | staging-сборка сайта получает `VITE_FORM_ENDPOINT=https://forms.rebit-pro.ru/v1/mos-dizel/lead` |

Готово, когда: заявка со staging-формы видна в Mailpit со всеми полями и utm; чужой origin получает 403; шквал запросов — 429; при остановленном SMTP заявка не теряется, а досылается.
