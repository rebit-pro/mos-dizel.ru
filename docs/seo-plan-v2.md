# SEO-план v2 для mos-dizel.ru — конкретизация к запуску 01.09.2026

Дата: 2026-08-24 · До запуска: 8 дней · Проект: ООО «ДТСНАБ» / МОС-ДИЗЕЛЬ · Исполнитель: студия ReBit.

Источники (по приоритету): анкета заказчика 23.08.2026 → `plan/semantics.md` (36 кластеров, 457 фраз) → `docs/competitors/mostransneft-ru.md` → `docs/seo-plan.md` (v1, рамочный) → `docs/discovery/*`. Этот документ **заменяет** v1 в части структуры, метаданных и порядка работ; v1 остаётся справочником по DoD и чек-листам этапов.

Правила честности, действующие на весь план: частотности/бюджеты/CTR не выдуманы — где нужна цифра, стоит «снять в Вордстате/Прогнозе бюджета»; ничего не обещаем сверх анкеты; каждая задача выполнима силами студии + владельца.

## 1. Решения по открытым вопросам v1 (сняты анкетой 23.08.2026)

| Вопрос v1 | Решение | Что это меняет в SEO |
|---|---|---|
| Показывать ли цену | **Цена не публикуется нигде**: ни на страницах, ни в мета, ни в объявлениях, ни в Schema.org | В title/description — расчёт, сроки, объёмы, документы. Никаких Product/Offer с price. Цена-запросы (15 фраз кластера 3) ведут на форму расчёта `/dizelnoe-toplivo/`. Слово «рассчитать стоимость» без цифр — допустимо |
| «Самая низкая цена» | Запрещено анкетой | Маски «дешевле всех / самое дешёвое» — в минус-лист (semantics 3.37.31); в текстах вместо этого только проверяемое: «паспорт качества завода-изготовителя — на каждую партию», «расчёт под объём». «Прямые поставки с НПЗ» — формулировка уровня 1 (design-concept 3.2): только после документального подтверждения — реальные договоры могут быть с нефтебазами/трейдерами |
| Мин/макс объём | **500 – 30 000 л** (не «от 300 л» из v1) | Оффер «от 500 литров» — свободная ниша по конкурентному отчёту; канистры/200 л — в минус |
| Срок доставки | **День в день + срочные и ночные** (не «2–3 часа» из v1/лендинга) | H1 лендинга «Доставка… за 2-3 часа» заменить; «2-3 часа» убрать из всех текстов и FAQ |
| Сегменты | **Все 8** приоритетные | 8 сегментных страниц; ДГУ+мероприятия — одна посадочная (урок каннибализации у конкурента) |
| «Солярка» | **Продвигаем** — слово клиентов по анкете | Страница `/solyarka/` в W1; опечатка «салярка» — только Директ, на сайте не публикуется |
| Марки топлива | Только летнее / межсезонное / зимнее | Отдельные URL по маркам; арктическое ДТ — открытый вопрос, до ответа в минус |
| Керосин | Клиенты спрашивают (анкета п.4), в ассортименте нет | **Открытый вопрос клиенту.** До ответа — в минус-лист; если «да» — страница `/kerosin/` в W2 |
| Бензин, печное топливо, отработка, СМТ | Не в ассортименте | НЕ продвигаем, минус-лист; печное и СМТ — подтвердить (открытые вопросы semantics 3, 4) |
| Оплата/документы | Безнал, НДС/без НДС, договор, счёт, УПД, ТТН, акт, паспорт качества, ЭДО | Кластер 11 → `/dizelnoe-toplivo-s-nds/` в W1 (свободная ниша конкурента); документы — обязательный блок каждой коммерческой страницы |
| Путь клиента | Звонок или короткая заявка; расчёт на сайте предварительный | Никакой корзины/оплаты; форма расчёта → Email; кнопки WhatsApp/Telegram на всех страницах; каждая точка контакта — цель Метрики |
| Материалы | «Все материалы будут генерированы нейросетью» | ⚠ Риск честности: нейро-изображения нельзя подавать как реальные фото автопарка/документов/команды в блоках доверия, OG и Schema. Реальные доказательства (паспорта качества, договоры, ТТН без чувствительных данных) — сканы настоящих документов. Отзывы — только реальные (со старого сайта + новые с именем/городом/компанией). Требование к дизайну «как будто работаем с Лукойл/Газпром/Роснефть/Татнефть» в SEO-тексты **не переносим**; бренды НПЗ и утверждения о происхождении («крупнейшие НПЗ», «прямые поставки с заводов») в тексты не берём вовсе, пока происхождение не подтверждено документами (уровни 0/1 design-concept 3.2) — проверяемая формулировка сейчас: «паспорт качества завода-изготовителя — на каждую партию» |
| Домены dtcnab.ru / top-diz.ru | Главный — mos-dizel.ru | 301-редиректы через DNS-уровень (раздел 3.4), клиент даёт доступ к DNS |

## 3. Техническое SEO: Vue/Vite на GitHub Pages

Текущее состояние (проверено по репо): SPA без пререндера — бот видит пустой `<div id="app">`; один роут `/`; в роутере живут шаблонные `/main`, `/starter`, `/error`, auth-страницы Berry; `public/_redirects` — Netlify-синтаксис, на GH Pages не работает; sitemap из 1 URL; canonical нет; Schema нет; 3 семейства Google Fonts.

### 3.1. Пререндер к 01.09 (решение)

**W0 (8 дней): снапшот-пререндер поверх готовой сборки, без изменения архитектуры приложения.**

- Скрипт `scripts/prerender.mjs` (playwright или puppeteer): после `vite build` поднимает `vite preview`, обходит список маршрутов из единого конфига `src/seo/pages.ts`, ждёт отрисовки `#app`, сохраняет полный HTML в `dist/{route}/index.html`.
- Head-менеджмент: подключить `@unhead/vue` (работает на клиенте; снапшот фиксирует уже подставленные title/description/canonical/OG/JSON-LD). Один источник правды — `src/seo/pages.ts`: `{ path, title, description, ogImage, schema }` — из него же генерируются sitemap и список маршрутов пререндера.
- Критерий приёмки: `curl -s https://mos-dizel.ru/ | grep '<h1'` возвращает H1; в HTML присутствуют тексты блоков, title и JSON-LD без выполнения JS.
- Для W0 пререндерится один маршрут `/` — риск минимальный, механика сразу готова к W1.

**W1+: тот же снапшот-пререндер по растущему списку маршрутов.** Маршруты W1 — обычные lazy-роуты vue-router; каждый получает свой файл `dist/<route>/index.html`, GH Pages отдаёт его как статику (реальный HTML по прямому заходу, SPA-навигация после гидрации). Миграция на vite-ssg/Nuxt — только если снапшоты станут узким местом (десятки страниц, медленная сборка); решение отложено сознательно, чтобы не менять стек за 8 дней.

Обязательная чистка к W0: удалить из прод-сборки `MainRoutes` (`/main`, `/starter`), auth-шаблоны и демо-views Berry; `/:pathMatch(.*)` → честная 404-страница. Удалить `public/_redirects`; добавить `public/404.html` (GH Pages отдаёт его со статусом 404 — это правильно для SEO; SPA-fallback-хак с редиректом из 404 не применять, т.к. все реальные URL имеют физические файлы после пререндера).

### 3.2. Canonical и зеркала

- На каждой странице `<link rel="canonical" href="https://mos-dizel.ru{path}/">` — абсолютный, с завершающим слэшем (естественная форма GH Pages `dir/index.html`). Внутренние ссылки — только канонический вид.
- GH Pages: включить Enforce HTTPS; DNS: apex A-записи Pages + `www` CNAME → GH Pages автоматически 301-ит www→apex (проверить после переключения DNS).
- Старый canonical `http://dtcnab.ru` больше нигде не фигурирует (проверка grep по сборке).

### 3.3. robots.txt и sitemap.xml

- `robots.txt` (уже близок к нужному): `User-agent: * / Allow: /` + `Sitemap: https://mos-dizel.ru/sitemap.xml`. Disallow не нужен — служебные маршруты физически удаляются из сборки (не «закрываем в robots», а не публикуем).
- `sitemap.xml` генерируется на сборке из `src/seo/pages.ts` (скрипт `scripts/sitemap.mjs`): только опубликованные индексируемые URL, только `<loc>` — без выдуманных lastmod/changefreq/priority. Политика ПДн и 404 в sitemap не включаются. После каждого релиза волны — переотправка в Вебмастер/GSC.

### 3.4. Редиректы dtcnab.ru и top-diz.ru (ограничение GH Pages)

GH Pages не умеет серверные 301 для чужих доменов — решаем на уровне DNS старых доменов (доступ даёт клиент, открытый вопрос v1 12.1):

1. **Основной вариант — Cloudflare Free на оба старых домена**: перенести DNS, включить проксирование, настроить Redirect Rule `(http|https)://(www.)?dtcnab.ru/* → 301 https://mos-dizel.ru/` (сайты одностраничные — карта URL тривиальна: всё на главную; если у top-diz.ru в индексе есть внутренние URL — снять список через `site:top-diz.ru` и решить поштучно). Hosting/Tilda при этом можно отключить.
2. Альтернатива, если у клиента остаётся хостинг старых доменов: 301 в nginx/панели хостинга.
3. Слабый запасной вариант (если доступ к DNS не дадут до 01.09): на Tilda-странице dtcnab.ru выставить canonical на `https://mos-dizel.ru/` и баннер переезда; это не 301 — вернуться к варианту 1, как только появится доступ.
4. После включения 301: в Яндекс.Вебмастере для dtcnab.ru — «Переезд сайта» на mos-dizel.ru; в GSC — Change of address (если dtcnab.ru был подтверждён).

### 3.5. OG-теги

На каждой странице: `og:title` (= title), `og:description` (= description), `og:url` (canonical), `og:type=website`, `og:locale=ru_RU`, `og:site_name=МОС-ДИЗЕЛЬ`, `og:image` — брендовый баннер 1200×630 (логотип + оффер «от 500 до 30 000 л, день в день»). ⚠ В og:image не использовать нейро-изображения, стилизованные под реальные фото автопарка. `twitter:card=summary_large_image`.

### 3.6. Schema.org (JSON-LD, через `src/seo/pages.ts`)

- **LocalBusiness** — на `/` и `/contacts/`: name «МОС-ДИЗЕЛЬ», legalName «ООО "ДТСНАБ"», taxID 5027259539, url, logo, telephone, email, address (МО, Люберецкий р-н, р-п Октябрьский — сверить актуальность с клиентом), areaServed «Москва и Московская область», sameAs (Яндекс Бизнес, 2ГИС — добавить после создания карточек). openingHoursSpecification — НЕ задавать: анкета подтверждает ночные ПОСТАВКИ, но не круглосуточный ПРИЁМ заявок, а данные старого сайта устарели; добавить только после ответа клиента о ночном дежурстве (открытый вопрос №8) — одновременно с «круглосуточно» в description `/contacts/` и уточнением Директа «Приём заявок 24/7». **Без priceRange, без Product/Offer** — цена не публикуется, размечать нечего; Offer без price невалиден и рискован.
- **FAQPage** — только на страницах с реально видимым FAQ-аккордеоном; вопросы уникальны для каждой страницы.
- **BreadcrumbList** — все страницы W1+ (Главная → Страница; для блога Главная → Блог → Статья). На W0 не нужен.
- **Article** — статьи блога (headline, datePublished реальная, author — реальное имя согласованного автора; безымянные статьи у конкурента — антипример).
- **Review/AggregateRating — не размечать**, пока на `/reviews/` нет отзывов с датами и полными данными; битая разметка отзывов у конкурента лишила его сниппета — не повторять.
- Все схемы прогонять через валидатор (validator.schema.org + проверка в Вебмастере) перед релизом волны.

### 3.7. Производительность (влияет на ранжирование и конверсию)

- Шрифты: не более двух семейств строго по дизайн-токенам (Manrope + Inter) вместо трёх Google-семейств; самохостинг woff2-субсетов (кириллица + латиница), `font-display: swap`; preconnect к Google Fonts при самохостинге не нужен.
- Изображения: WebP/AVIF, ленивая загрузка ниже первого экрана, явные width/height; hero-изображение — приоритетная загрузка (LCP).
- Vuetify уже tree-shaken (`vite-plugin-vuetify`); проверить, что в бандл не тянутся демо-компоненты Berry после чистки роутов.
- Цель: Lighthouse SEO и Performance 90+ на `/` к 01.09 и на каждой W1-странице к её релизу (DoD из v1 сохраняется).
