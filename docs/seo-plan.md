## 1. Цель SEO

Перевести проект из формата одного лендинга в индексируемый сайт с понятной структурой страниц, где каждая страница закрывает отдельное поисковое намерение: купить дизельное топливо, заказать доставку, подобрать сезонную марку, получить топливо для конкретного объекта, заказать оборудование или проверить надежность поставщика.

Главная SEO-задача: не просто добавить метатеги, а заранее спроектировать структуру, контент, техническую индексацию, аналитику и миграцию доменов так, чтобы поисковые системы корректно сканировали сайт, а клиент видел результат в заявках.

## 2. Что нужно собрать до полноценного SEO-исследования

### 2.1. Данные о бизнесе и продажах

- Юридическое название, ИНН, ОГРН, адрес, актуальные реквизиты.
- Основной бренд на сайте: `МОС-ДИЗЕЛЬ`, `ДТСНАБ` или связка брендов.
- Основной домен: `mos-dizel.ru`.
- Что делать с доменами `dtcnab.ru` и `top-diz.ru`: редирект, сохранение, закрытие, отдельный сайт.
- Актуальный телефон, email, мессенджеры, график приема заявок.
- География поставок: Москва, вся Московская область, конкретные города, трассы, районы.
- Минимальный и максимальный объем поставки.
- Формы оплаты: наличный/безналичный расчет, НДС, ЭДО, отсрочка, договор.
- Список услуг, которые реально продаются сейчас.
- Список услуг, которые нельзя продвигать, даже если они есть у конкурентов.
- Сезонность спроса: летнее, межсезонное, зимнее топливо, пики спроса.

### 2.2. Ассортимент и офферы

- Актуальные виды топлива: ДТ C, ДТ E, ДТ F, ДТЗ, Евро-5, другие марки.
- Актуальные цены или правило показа цены: открытая цена, "от ...", только расчет менеджером.
- Разница между "дизельное топливо", "солярка", "ДТ" в коммуникации клиента.
- Есть ли отдельные офферы для юрлиц, частных домов, строек, котельных, транспорта, генераторов.
- Нужны ли отдельные страницы под мини-АЗС и еврокубы.
- Какие преимущества можно подтверждать документально: паспорт качества, арбитражная проба, счетчики, GPS, пломбы, собственный автопарк, договоры.

## 3. Текущие SEO-риски проекта

1. Сейчас проект является Vue/Vite SPA. Для многостраничного SEO-сайта нужно проверить, видит ли бот контент в исходном HTML. Если страницы отрисовываются только в браузере, нужен пререндеринг/SSG или переход на SSR/SSG-подход.
2. GitHub Pages удобен для статического деплоя, но ограничен для серверных 301-редиректов. Если будет SEO-миграция со старых доменов и сохранение URL-веса, редиректы нужно решать на уровне DNS/CDN/хостинга или отдельного сервера.
3. В текущих материалах есть конфликт цены: `48 р/л` в hero и `от 35 руб./л` в старом meta description. До SEO-текстов цену нужно подтвердить.
4. Необходимо определить главный бренд и юридическую сущность, чтобы не смешивать `МОС-ДИЗЕЛЬ`, `ДТСНАБ`, `dtcnab.ru` и `top-diz.ru` в сниппетах.
5. Старый canonical `http://dtcnab.ru` должен быть заменен на канонический `https://mos-dizel.ru/`.
6. На текущем лендинге часть секций уже хороша для SEO, но для расширения сайта их нужно разнести по кластерам и страницам.

## 5. Шаблон SEO-проработки каждой страницы

Для каждой будущей страницы фиксируем:

- URL.
- Поисковое намерение.
- Основной ключ.
- Вторичные ключи.
- География.

- Внутренние ссылки: куда ведем пользователя дальше.
- Schema.org тип.
- Доказательства доверия на странице.
- Целевое действие.

## 6. План работ по SEO

### Этап 1. Сбор данных и фиксация ограничений

Результат: заполненный бриф по бизнесу, конкурентам, семантике, доменам, доступам и контенту.

Задачи:

- Получить ответы на открытые вопросы из раздела 12.
- Подтвердить доменную стратегию.
- Подтвердить актуальные цены, виды топлива, географию.
- Подтвердить, какие отзывы, логотипы клиентов и документы можно публиковать.
- Зафиксировать список запрещенных тем и нежелательных слов.

### Этап 2. Анализ конкурентов

Результат: таблица конкурентов и карта сильных/слабых решений.

Задачи:

- Проверить топ выдачи Яндекса и Google по основным запросам.
- Разделить конкурентов на прямых поставщиков, агрегаторы, справочники и информационные сайты.
- Вытащить структуру страниц конкурентов.
- Сравнить офферы, цены, CTA, доверие, документы, географию.
- Определить, какие страницы нужны для борьбы за выдачу, а какие будут пустой тратой бюджета.

### Этап 3. Семантическое ядро и кластеризация

Результат: таблица "кластер -> страница -> ключи -> приоритет".

Задачи:

- Собрать базовые ключи из клиентского списка, Wordstat/поисковых подсказок/конкурентов.
- Разделить ключи на коммерческие, гео, сезонные, отраслевые, информационные.
- Убрать мусорные запросы: нецелевые регионы, неподходящие продукты, вакансии, рефераты, сервисы АЗС.
- Определить приоритеты: страницы, которые нужны сразу, и страницы второй очереди.
- Привязать каждый кластер к будущему URL.

### Этап 4. Проектирование структуры сайта

Результат: sitemap-план будущего сайта.

Задачи:

- Утвердить структуру из раздела 4 после анализа семантики.
- Определить, какие страницы создаются в первой версии сайта.
- Определить правила URL: транслит, нижний регистр, без дат и технических параметров.
- Спроектировать хлебные крошки и внутреннюю перелинковку.
- Спроектировать 404-страницу и маршруты для старых URL.

### Этап 5. Техническое SEO

Результат: сайт корректно сканируется и индексируется.

Задачи:

- Проверить серверный/статический HTML для каждой SEO-страницы.
- Для Vue/Vite выбрать решение: пререндеринг маршрутов, SSG или миграция на Nuxt/другой SSR/SSG-подход.
- Настроить уникальные title, description, canonical и OG для каждой страницы.
- Подготовить `robots.txt` с ссылкой на sitemap.
- Подготовить `sitemap.xml` со всеми индексируемыми URL.
- Настроить canonical `https://mos-dizel.ru/...`.
- Исключить из индекса служебные страницы: `/main`, `/starter`, auth-шаблоны, технические маршруты.
- Настроить 404 и проверить статус-коды.
- Проверить внутренние ссылки как реальные `<a href>`.
- Оптимизировать изображения: размер, WebP/AVIF, alt, lazy-loading ниже первого экрана.
- Добиться Lighthouse SEO и Performance 90+ на ключевых страницах.

### Этап 6. Контент и метаданные

Результат: контент-карта и тексты для посадочных страниц.

Задачи:

- Для каждой страницы написать H1, title, description, структуру H2/H3.
- Написать тексты без переспама, с нормальным ответом на намерение пользователя.
- Добавить FAQ там, где он реально виден на странице.
- Добавить таблицы марок топлива, условия поставки, документы.
- Подготовить alt для изображений.
- Подготовить перелинковку между услугами, сезонными страницами, задачами клиентов и блогом.

### Этап 7. Schema.org

Результат: валидная JSON-LD разметка.

Рекомендуемые типы:

- `Organization` или `LocalBusiness` для компании.
- `BreadcrumbList` для страниц с иерархией.
- `FAQPage` только для страниц, где FAQ реально отображается.
- `Product`/`Offer` осторожно: только если есть конкретный продукт, цена/условия и они соответствуют видимому контенту.
- `Article`/`BlogPosting` для статей.

Все схемы проверять валидатором и не размечать то, чего нет на странице.

### Этап 8. Миграция доменов и запуск

Результат: новый домен не теряет накопленный спрос и корректно попадает в индекс.

Задачи:

- Утвердить судьбу `dtcnab.ru` и `top-diz.ru`.
- Составить карту старых URL -> новых URL.
- Настроить 301-редиректы, если есть доступ к старым доменам.
- Проверить `http -> https`, `www -> non-www` или наоборот.
- Проверить canonical после деплоя.
- Отправить sitemap в Яндекс.Вебмастер и Google Search Console.
- Проверить индексацию через `site:mos-dizel.ru`.
- В первые 2-4 недели после запуска отслеживать ошибки обхода и исключенные страницы.

### Этап 9. Аналитика и KPI

## 10. Технические требования к реализации

- Все SEO-страницы должны иметь статический HTML на момент загрузки или корректный пререндер.
- Для каждой страницы: один H1, корректная иерархия H2/H3.
- У каждой страницы: уникальные title, description, canonical, OG.
- Главный язык: `ru`.
- URL: человекопонятные, без query-параметров для основных страниц.
- Внутренние ссылки: обычные ссылки с `href`.
- `robots.txt` должен разрешать индексацию продакшена и ссылаться на sitemap.
- `sitemap.xml` должен содержать только индексируемые страницы с каноническими URL.
- Служебные шаблонные страницы Berry/Vuetify не должны попасть в индекс.
- Изображения первого экрана должны быть оптимизированы, чтобы не ломать LCP.
- Формы должны иметь события аналитики и понятное состояние успешной отправки.
- Политика обработки персональных данных должна быть доступна с форм.

## 11. Definition of Done для SEO

- Утверждена структура сайта и карта URL.
- Семантика кластеризована и привязана к страницам.
- Для каждой страницы подготовлены title, description, H1, структура H2/H3.
- Все SEO-страницы доступны в HTML для ботов.
- `robots.txt`, `sitemap.xml`, canonical и редиректы настроены.
- Старые домены и URL имеют понятную миграционную стратегию.
- Schema.org внедрена и валидна.
- Lighthouse SEO и Performance 90+ на ключевых страницах.
- Яндекс.Метрика/GA4 подключены, цели настроены.
- Сайт добавлен в Яндекс.Вебмастер и Google Search Console.
- После запуска проверены ошибки сканирования и индексации.
